# 002 — Ontology index; no prefix registered

## PR

### Summary

The package moves to core's ontology module layout and registers no prefix: an app lists the
prefixes it uses in its own prefix map.

- `src/ontologies/org.ts`: regenerated by `linked generate-ontology`; each term is `export const X = {id: '<full IRI>'}`, the module imports nothing.
- `src/ontologies/index.ts` (generated): registers org (45) with `registerOntologies([...], import.meta.url)`: name, namespace, terms, data files, suggested prefix. The entry and `src/shapes/index.ts` import it.
- Removed: `org.data.ts`, `org.register.ts` (`ns`, `dataFiles`, `loadData`, `_ontologyResource`, and the prefix they added). `src/package.ts` exports `registerOntologies` instead of `linkedOntology`.
- `test/ontology-data.test.mjs` read `ns`, `dataFiles`, `loadData` from the removed data module; it now reads the registration (`getRegisteredOntologies()`: namespace, suggested prefix, files, `load()`) and a term from `ontologies/org`.
- README: the module paragraph describes the index, terms as literals, no prefix registered, and core's `createNameSpace` for a namespace function.
- Changeset `.changeset/ontology-index-no-prefix.md` (major), beside the pending patch from the vann step.
